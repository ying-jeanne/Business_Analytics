3. Data: Samples vs Features

▼

📈 More Samples (Rows)

  • Benefit: Better estimates if similar distribution to future
  • Cost: Lower quality if different distribution
  • Rule: Closer to future = more similar distribution (usually)
  • Strategy: Try and test - depends on specific data

📊 More Features (Columns)

  • Benefit: More related features = better predictions
  • Cost: More unknowns = harder to estimate (usually)
  • Exception: Sometimes more features make problem easier
  • Counterintuitive: 115,294 features with 17 samples can work!

🏢 Real-World Examples

  • Meituan Success: Cross-category data aggregation improved forecasting
  • Taobao Application: Similar cross-product benefits
  • M4 Dataset: 96% improvement over equal weighting, 50% cases 6.5x better
  • Ensemble Learning: Wisdom of crowds - aggregate different predictions

🔧 Practical Data Enhancement

  • Free Methods: Forecast aggregation, cross-category pooling
  • External Data: Google Maps ratings/reviews for rent prediction
  • LLM Help: Convert unstructured (text/images) to structured data
  • Key Insight: Biggest improvements often come from changing data

If Error > 0: Loss = Cost × Error
If Error < 0: Loss = (Price - Cost) × (-Error)

🔢 Mathematical Optimization Examples

  • L2 Loss → Mean: Minimizing sum of squared errors gives arithmetic mean
  • L1 Loss → Median: Minimizing sum of absolute errors gives median
  • Outlier Sensitivity: Mean sensitive to outliers, median robust
  • First-Order Condition: Set derivative = 0 to find minimum
  • Newsvendor → Pinball Loss: 20% + 80% = 100% (required scaling)
Key Mathematical Results:
L2 Loss: z* = mean = (1+5+7+100)/4 = 28.25
L1 Loss: z* = median = between 5 and 7
Pinball Loss: Asymmetric penalties drive optimal predictions

🎯 Pinball Loss Mathematical Theory

  • τ-Pinball Loss Definition: lτ(ε) = {(1-τ)ε if ε>0, τ(-ε) if ε<0}
  • Parameter Relationships: τ=50% gives L1 loss (absolute value)
  • Quantile Connection: τ sample quantile minimizes τ-pinball loss
  • Asymmetric Penalties: Different costs for over/under estimation
  • Business Application: Newsvendor model as special case of pinball loss
Pinball Loss Formula:
lτ(ε) = {(1-τ)ε if ε > 0, τ(-ε) if ε ≤ 0}
where ε = actual - prediction, τ ∈ [0,1]

📊 Quantile Regression Applications

  • 50% Quantile (τ=0.5): Equivalent to L1 loss, gives median
  • 90% Quantile (τ=0.9): Heavy penalty for underestimation
  • 10% Quantile (τ=0.1): Heavy penalty for overestimation
  • Visualization Insight: Different τ values create different "elbow" shapes in loss function
  • Practical Choice: Select τ based on business cost structure

📈 Linear Regression Advantages

  • Interpretability: Clear coefficient meanings for business insights
  • Simplicity: Easy to explain to stakeholders and decision makers
  • Robustness: Well-understood theoretical properties
  • Efficiency: Fast computation even with large datasets
  • Baseline Performance: Often surprisingly competitive with complex models

🏠 Linear Regression: Prediction vs Inference

  • Prediction Focus: Care about future loss, performance on new data
  • Inference Focus: Confidence intervals of coefficients, no future data
  • Linearity Assumption: Prediction tolerates non-linear reality; inference requires strict linearity
  • Design Types: Random design (prediction) vs Fixed design (inference)
  • Key Question: Do loss-prediction correspondences remain true in linear regression?

📈 Empirical Evidence: Symmetric vs Asymmetric Loss Behavior

  • L1/L2 Results: Symmetric loss leads to roughly unbiased errors (centered at 0)
  • Pinball 5% vs L1: Almost all points satisfy 5% pinball prediction < L1 prediction
  • Pinball 95% vs L1: Almost all points satisfy 95% pinball prediction > L1 prediction
  • Theoretical Confirmation: Larger penalty for overestimation → underestimate strategy
  • Business Validation: Asymmetric penalties drive directional prediction bias as expected

🔧 How to Elicit τ (Pinball Parameter Selection)

  • Confidence Intervals: For 95% CI, choose τ = [2.5%, 97.5%]
  • General Rule: Minimize τ-Pinball loss means Prob(Predτ ≥ Truth) ≈ τ
  • Cost-Based: GetGo + Watermelon examples show cost ratio determines τ
  • Percentage-Based: Clearing house example uses acceptable over/underestimation rates
  • Iterative Process: Implement → Feedback → Improvement → Feedback →...

📊 Relative Error and MAPE (Mean Absolute Percentage Error)

  • Business Need: Boss/client wants percentage measurements, not absolute errors
  • Formula: Relative Error = (Prediction - Truth) / Truth
  • Example: (330K - 300K) / 300K = 10%
  • Weighted L1 Loss: ∑(1/Truth_i)|z - Truth_i| gives MAPE optimization
  • Key Insight: Smallest values become most important in relative error minimization

⚠️ L2 Loss for Relative Error (Rarely Used)

  • Formula: ∑(1/Truth_i²)(z - Truth_i)² for weighted L2 loss
  • Weight Impact: L2 relative error makes observation "1" 10,000× more important than "100"
  • L1 vs L2 Weighting: L1 relative: 100× difference; L2 relative: 10,000× difference
  • Practical Issue: Extreme emphasis on small values often unrealistic
  • Usage Note: "Not Very Often Used" in practice due to extreme weighting

🏠 HDB Resale MAPE Results

  • Training Performance: MAPE = 5.16% (average percentage error)
  • Error Distribution: Roughly symmetric around 0, centered distribution
  • Business Context: 99.co provides HDB price predictions with X-Value service
  • Commission Model: 0.1% rate → S$500K sale = S$500 revenue
  • Platform Description: Digital property advertising/marketplace with premium features

🚨 Caution: When Is MAPE Inappropriate?

  • Core Issue: Predicting small values becomes disproportionately important
  • Critical Check: Always verify if any truth values are close to 0
  • Validation Step: Create histogram of truth/target values to ensure no near-zero values
  • Decision Consistency: Ask "Is this weighting consistent with decision objective?"
  • Example Problem: (1,5,7,100) data makes predicting "1" 100× more important than "100"

💰 Cash Flow vs Sales MAPE Problem

  • Context: Budget-making assistant for business planning
  • Observation: Cash flow MAPE much larger than sales MAPE
  • Root Cause: Cash flow includes values close to 0, sales values consistently large
  • Decision Mismatch: Budget planning cares about absolute amounts, not percentages
  • Conclusion: MAPE reasonable for sales, inappropriate for cash flow

📈 Cash Flow MAPE Failure Example

  • Data: Truth values: [100, 100K, 110K, 150K, -110K], Perfect predictions except first
  • Error: Only 1st observation off by 1000 (prediction 1100 vs truth 100)
  • MAPE Result: 1000%/5 = 200% (misleadingly terrible performance)
  • Reality: 4/5 predictions perfect, only small absolute error on one observation
  • Lesson: Problem is MAPE's inappropriateness, not prediction quality

🔧 MAPE Improvements and Alternatives

  • SMAPE: Symmetric MAPE = (1/T)∑|Ft-Yt|/((|Yt|+|Ft|)/2)
  • MASE: Mean Absolute Scaled Error, scales by naive forecast performance
  • MASE Formula: mean(|Ft-Yt|/(1/(T-1)∑|Yt-Yt-1|))
  • Reporting Strategy: "Lowest to show good performance" (choose best metric)
  • LLM Recommendation: Use AI tools to research additional error metrics

💻 Implementation: Sample Weights

⚖️ Bias-Variance Tradeoff: Classic Curve Analysis

  • Training Loss Trend: Blue line decreasing (more freedom fits training data better)
  • Underfitting vs Overfitting: Too many constraints vs too few constraints
  • Sweet Spot: Belief in optimal point between bias and variance tradeoff
  • Gap Explanation: Why blue line below red line (training vs test performance)

📉 Overfitting Definition & Detection

  • Definition: Fits training set too closely + fails to generalize to test set
  • Critical Importance: Avoiding overfitting is critical for supervised learning
  • Mathematical Sign: Loss(train) ≪ (much smaller) Loss(test)
  • Bias-Variance Characterization: Low bias + high variance
  • Mechanism: As train data change, predictions change too much

📏 Rule-of-Thumb for Linear Regression Overfitting

  • Safety Rule: No severe overfitting concern when #observations ≥ 10 × #features
  • Simulation Context: Visualization used #observations = 2 (extreme case)
  • HDB Example: #observations ≈ 16,000 → safe up to ~1,600 features
  • Loss Independence: Rule applies regardless of loss function choice
  • Practical Application: Use for feature selection planning

🎯 Final Framework Summary: Past → Future Connection

  • Core Logic: If Train Loss ≈ Test Loss → minimize Train Loss might work
  • Key Insight: Best past performance might lead to great future performance
  • Shared Randomness: Train and test data share same randomness
  • Reality Check: "They could be horrible but similar"
  • Training Motivation: "This explains why we always want to minimize training loss"

🛠️ Overfitting Solution: Constraints Preview

  • Problem: Sometimes minimized Train Loss ≪ its Test Loss
  • Failure Mode: Best historical performance fails to lead to great test performance
  • Root Cause: It fits the past too well (high variance)
  • Solution Toolkit: Constraints (covered in next week's material)
  • Mechanism: Predictions cannot change freely → variance reduced when train data change

🎯 How to Elicit τ (Tau Parameter Selection)

  • Confidence Interval Method: For 95% CI → τ₁ = 2.5%, τ₂ = 97.5%
  • General Rule: Minimize τ-Pinball loss means Prob(Predτ ≥ Truth) ≈ τ
  • Mathematical Relationship: Prob(Predτ₁ ≤ Truth ≤ Predτ₂) ≈ 97.5% - 2.5% = 95%
  • Business Considerations: Cost of overestimation vs underestimation
  • Practical Application: Percentage of acceptable over/underestimation
Confidence Interval Formula:
τ₁ = 2.5% → Prob(Predτ₁ ≥ Truth) ≈ 2.5%
τ₂ = 97.5% → Prob(Predτ₂ ≥ Truth) ≈ 97.5%
Combined: 95% Confidence Interval

📊 Relative Error Metrics Overview

  • Key Advantage: Most important feature of relative error - easy to understand
  • MAPE: Mean Absolute Percentage Error
  • SMAPE: Symmetric Mean Absolute Percentage Error
  • MASE: Mean Absolute Scaled Error
  • WMAPE: Weighted Mean Absolute Percentage Error
  • Reporting Strategy: "The lowest among the appropriate ones"

⚖️ Relative Error Weighting Analysis

  • Mathematical Structure: |z-1|/1 + |z-5|/5 + |z-7|/7 + |z-100|/100
  • Weighted Form: (1/1)|z-1| + (1/5)|z-5| + (1/7)|z-7| + (1/100)|z-100|
  • Key Insight: Different samples have different weights
  • Preference Structure: Samples with small truth values more important than large values
  • Critical Question: Is this weighting consistent with decision objective?

🚨 When MAPE is Inappropriate

  • Danger Signal: Histogram shows few values extremely close to 0
  • Problem: These few samples become extremely important
  • Consequence: All other samples become unimportant
  • Reality Check: "This preference for loss is never correct in real-world setting"
  • Detection Method: Always check histogram of truth/target values first

📈 MAPE Failure Example

  • Data Setup: Truth=[100, 100K, 110K, 150K, -110K], Pred=[1100, 100K, 110K, 150K, -110K]
  • Error Analysis: Only 1st observation off by 1000, others perfect
  • MAPE Result: 1000%/5 = 200% (misleadingly terrible)
  • Reality: 4/5 predictions perfect, small absolute error on one observation
  • Key Lesson: Problem is MAPE inappropriateness, not prediction quality

🔧 Feature Engineering: Three Strategic Approaches

  • Error/Residual Analysis: For linear regression - there shall be no clear pattern in errors
  • Intuition & Domain Knowledge: Satellite imagery for Walmart sales, oil price, crop yield prediction
  • Exploratory Data Analysis (EDA): Rain forecast for taxi assignment optimization
  • Goal: Engineer features that capture meaningful business relationships
  • Validation: Verify no systematic patterns remain in residuals

🎯 Target Variable Transformation Strategy

  • Price vs Return: Predict tomorrow's price directly OR predict the return
  • Sales vs Growth: Predict next year's sales directly OR predict year-to-year growth
  • Cumulative vs Arrival: Predict cumulative luggage on belt OR predict customers' arrival
  • Key Question: Which approach more likely to have past and future share same randomness?
  • Strategic Consideration: Choose target that maintains distributional stability

🚫 Cardinal Rule: No Future Information

  • Fundamental Principle: Do not use future information to predict future target
  • Context Dependency: Definition of "future information" depends on prediction task
  • 90-Day Forecast: Need to predict demand 90 days in advance using only available data
  • Data Form: Learn patterns from transaction records, then apply them
  • Critical Timing: What information is actually available at prediction time?

📅 Temporal Data Handling Examples

  • Wrong Approach: 2025-01 to 2025-07 as train, 2025-08 as test - is this OK?
  • Key Question: Isn't 'date' future information?
  • Correct Features: avg_price_90_day_before, avg_review_score_90_day_before
  • LLM Limitation: "LLM could not make the two tables consistent..."
  • Proper Lag: Use historical aggregations with appropriate time windows

🏠 HDB Features: Future Information Analysis

  • Question: Are HDB features (floor_area_sqm, flat_model, lease_commence_date, remaining_lease) future information?
  • Answer: No - these are known at prediction time
  • Successful Example: Date and HDB features could be seen as successful use of available information
  • Caution: Predicting future features first might not be good idea
  • Complexity Issue: Many future features → need many algorithms (one for each)

⏰ Time Horizon Comparison: 90-Day vs 30-Min

  • Demand Prediction: 90-day advance → 90-day before data acceptable
  • Order Consolidation: 30-min advance → 30-min before (immediate after order) acceptable
  • Key Insight: Prediction horizon determines what constitutes "future" information
  • Business Context: Order consolidation can use more recent data than demand forecasting
  • Practical Application: Adjust feature engineering based on prediction timeline

📊 Why Future Information Generates Stellar Results

  • Experience vs Science: Empirical observation rather than theoretical understanding
  • Simple Example: If quantity = 2 for all transactions
  • Information Advantage: Knowing how many users buy → perfectly predict total quantity
  • Hidden Knowledge: Transaction data reveals other users' quantity = 0
  • Information Value: "A huge amount of information" leaked from future

🎓 Student Data Leakage Warning

  • Common Pattern: "You could not believe how many students just split data, run algorithms, get stellar results, declare victory"
  • LLM Contribution: "This might happen due to the use of LLM"
  • False Confidence: Suspiciously good results often indicate data leakage
  • Proper Validation: Always verify temporal consistency and information availability
  • Academic Warning: Results too good to be true usually are

8. Key Concepts Summary

🎯 Critical Insights for Quiz

  • Framework Foundation: Data + Loss + Structure + Constraints
  • Past-Future Link: Same underlying randomness enables prediction
  • Data Strategy: More samples good if similar distribution
  • Feature Paradox: More features can sometimes make problems easier
  • Constraint Power: Even wrong constraints can improve predictions
  • Bias-Variance: Constraints typically reduce variance
  • High Dimensions: Counter-intuitive behavior vs low dimensions

🤔 Key Questions to Consider

Q1: Why can we use past data to predict the future?
A: Same underlying randomness/distribution between past and future
Q2: When are more samples beneficial?
A: When they come from similar distribution as the future data
Q3: Can wrong constraints help predictions?
A: Yes! They can reduce variance even if they increase bias
Q4: What's the bias-variance decomposition?
A: Squared Error (L2) = Bias² + Variance (always true)

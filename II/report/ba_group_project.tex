\section*{Abstract}
\noindent This project develops a cost-sensitive credit default prediction system using the UCI Credit Card dataset. We implement and compare five models: three glassbox models (Linear Regression with L2 loss—also known as Ridge Regression, Logistic Regression with log-loss, and Linear SVM with hinge loss), and two blackbox models (LightGBM with L2 loss and LightGBM with cross-entropy loss). The selected model (LightGBM with cross-entropy loss) achieves 0.7642 validation AUC and 0.7659 test AUC. Using a custom business cost function based on 50\% Loss Given Default and 10\% profit margin (5:1 cost ratio), we optimize the decision threshold to minimize net business cost rather than misclassification error. At the cost-optimal threshold of 0.13, the model achieves \$5.75M net cash flow with 40.7\% approval rate and 10.5\% default rate among approved customers. SHAP analysis reveals that payment history features (MAX\_DELINQUENCY, PAY\_1) dominate prediction importance, providing interpretability for regulatory compliance and business decision-making.

%% 1. INTRODUCTION AND MOTIVATION
\section{Introduction and Motivation}

Credit card default prediction represents a critical challenge in consumer finance, where financial institutions must balance expected returns against non-payment risk. Misclassification costs are highly asymmetric: approving a defaulter (False Negative) typically results in 30-50\% loss of the credit limit, while rejecting a profitable customer (False Positive) represents a foregone profit opportunity of 10-15\% annually.

This project addresses the credit default prediction problem with three key objectives:

\textbf{Model Performance:} Implement and compare glassbox (interpretable linear) and blackbox (tree-based) models using multiple loss functions, selecting based on validation AUC rather than training loss to ensure generalization.

\textbf{Cost-Sensitive Optimization:} Design a custom evaluation loss function reflecting real business economics (Loss Given Default and profit margin) and optimize the decision threshold to minimize total cost rather than misclassification rate. We demonstrate via threshold analysis (Appendix \ref{app:cost_curves}) that traditional F1-score optimization misaligns with business objectives by more than 200\%.

\textbf{Interpretability and Transparency:} Apply SHAP (SHapley Additive exPlanations) analysis to the blackbox model, providing both global feature importance and local prediction explanations for regulatory compliance and business understanding.

\textbf{Scope and Data Filtering:} We focus on customers with credit limits $\leq$ \$200,000 (67.9\% of the original dataset), targeting automated decision-making for small loans. Larger loans typically require manual review considering factors beyond the scope of this analysis (e.g., client background, collateral, social status). The filtered dataset contains 20,378 customers with 25.6\% default rate, split into 60\% training, 20\% validation, and 20\% test sets with stratification to maintain class balance.

\section{Data and Methods}
\subsection{Dataset Description}

The UCI Credit Card Default Dataset\footnote{Yeh, I.C., \& Lien, C.H. (2009). The comparisons of data mining techniques for the predictive accuracy of probability of default of credit card clients. \textit{Expert Systems with Applications}, 36(2), 2473-2480. Dataset available at: \url{https://www.kaggle.com/datasets/uciml/default-of-credit-card-clients-dataset}} contains payment information from 30,000 credit card clients in Taiwan from April to September 2005, with default status in October 2005 as the target variable. After filtering to credit limits $\leq$ \$200,000, our analysis uses 20,378 customers with 25.6\% default rate.

The dataset comprises 23 original features across four categories: demographics (4 features), credit information (1 feature), payment history (6 features), and transaction amounts (12 features). A comprehensive feature description table is provided in Appendix \ref{app:feature_table}.

Data Splits: Stratified sampling maintains 25.6\% default rate across all splits: Training (12,226), Validation (4,076), Test (4,076).

\subsection{Data Cleaning}

Comprehensive data quality checks were performed:

\begin{enumerate}[label=\alph*.]
    \item Missing Values: Zero missing values confirmed across all columns
    \item ID Uniqueness: Verified each customer has unique identifier
    \item Categorical Consolidation:
    \begin{itemize}[label=-]
        \item EDUCATION: Merged invalid categories (0, 5, 6) into 'others' (category 4)
        \item MARRIAGE: Merged category 0 into 'others' (category 3)
        \item PAY\_STATUS: Renamed PAY\_0 to PAY\_1 for temporal consistency
    \end{itemize}
    \item Range Validation: Checked age bounds (0-90 years), bill amounts (allowing negative as valid bank credit), payment amounts (non-negative confirmed)
    \item Class Imbalance: Acknowledged 3:1 imbalance (74.4\% non-default, 25.6\% default), addressed through class weighting in linear models and cost-sensitive threshold optimization with build-in function.
\end{enumerate}

\subsection{Feature Engineering}

Eight features were engineered to capture temporal trends and financial behavior patterns. For the ones named slope, we used Ordinary Least Squares (OLS) regression for slope calculations. These engineered features include payment trends, delinquency patterns, repayment behavior, and credit utilization metrics. Detailed descriptions are provided in Appendix \ref{app:engineered_features}.

\subsection{Preprocessing:}
\begin{itemize}
    \item Linear Models: One-hot encoding for categorical variables (SEX, EDUCATION, MARRIAGE), resulting in 34 features. Normalization applied to continuous features only (excluding boolean dummies). Feature-to-sample ratio: 34 features / 12,226 samples = 1:360, well above the 1:10 rule of thumb.
    \item Tree Models: No one-hot encoding (LightGBM handles categorical variables natively using category dtype), resulting in 31 features. No normalization required for tree-based methods.
\end{itemize}

\section{Model Development and Comparison}

\subsection{Model Specifications}

We implemented five models satisfying the requirement of at least one glassbox and one blackbox model, each with two loss function versions (L2 and a surrogate loss):

\textbf{Glassbox Models (Linear):}

\begin{enumerate}
    \item Ridge Regression (L2 Loss): Baseline regression approach treating classification as regression with L2 loss. Hyperparameter: alpha $\in$ \{0.001, 0.01, 0.1, 1, 10, 100, 1000\} selected via 5-fold cross-validation maximizing AUC.

    \item Logistic Regression (Log Loss): Probabilistic classifier with log-odds interpretability. Uses class\_weight='balanced' to handle class imbalance. Hyperparameter C $\in$ \{0.001, 0.01, 0.1, 1, 10, 100\} selected via 5-fold CV maximizing AUC.

    \item Linear SVM (Hinge Loss): Margin-based classification using squared hinge loss for stability. Uses class\_weight='balanced' to handle class imbalance. Calibrated with CalibratedClassifierCV (3-fold) to obtain probability estimates. Hyperparameter C $\in$ \{0.001, 0.01, 0.1, 1, 10, 100\} selected via 5-fold CV.
\end{enumerate}

\textbf{Blackbox Models (Tree-based):}

\begin{enumerate}
    \setcounter{enumi}{3}
    \item LightGBM Regressor (L2 Loss): Gradient boosting regression\footnote{Ke, G., Meng, Q., Finley, T., Wang, T., Chen, W., Ma, W., Ye, Q., \& Liu, T.Y. (2017). LightGBM: A highly efficient gradient boosting decision tree. \textit{Advances in Neural Information Processing Systems}, 30.} with MSE objective. Default hyperparameters used (100 estimators, learning rate 0.1).

    \item LightGBM Classifier (Cross-Entropy Loss): Gradient boosting classification with binary cross-entropy objective. Outputs calibrated probabilities directly. Default hyperparameters.
\end{enumerate}

All models trained on 12,226 samples and evaluated on validation set (4,076 samples) using AUC-ROC as the primary comparison metric per project requirements for model selection.

\subsection{Hyperparameter Tuning} 

\textbf{For linear model: }Given the 3:1 class imbalance even though not severe (25.6\% default rate), we used still decided to use the config class\_weight='balanced' for Logistic Regression and Linear SVM to automatically adjust sample weights inversely proportional to class frequencies: $w_i = \frac{n\_samples}{n\_classes \times n\_samples_i}$. We then performed 5-fold cross-validation grid search over the C parameter (inverse of regularization strength, where smaller C = stronger regularization):

\begin{itemize}
    \item Logistic Regression: C $\in$ \{0.001, 0.01, 0.1, 1, 10, 100\}, selected C=10
    \item Linear SVM: C $\in$ \{0.001, 0.01, 0.1, 1, 10, 100\}, selected C=1
    \item Ridge Regression: alpha $\in$ \{0.001, 0.01, 0.1, 1, 10, 100, 1000\}, selected alpha=1
\end{itemize}

\textbf{For tree models:} LightGBM models used default hyperparameters (100 estimators, learning rate 0.1) without grid search. Tree-based models handle class imbalance differently through their splitting criteria and do not require explicit class weighting or C-style regularization.

\subsection{Performance Comparison}

All five models were evaluated on the validation set (4,076 samples) using AUC-ROC as the primary metric. Table \ref{tab:model_comparison} in Appendix \ref{app:model_results} presents the complete results.

\textbf{Key Observations:}
\begin{itemize}
    \item Blackbox Superiority: LightGBM models outperform all linear models, with the Cross-Entropy variant achieving the highest AUC (0.7642), representing a 0.0194 improvement (2.7\% relative) over the best glassbox model
    \item Loss Function Effects: Within model families, surrogate losses (Cross-Entropy for trees, Log Loss for linear) consistently outperform L2 loss by 0.0043-0.0076 AUC points
    \item Class Balancing: Logistic Regression and Linear SVM benefit from class\_weight='balanced' to handle the 3:1 class imbalance
    \item AUC Interpretation: The selected model (LightGBM CE, AUC=0.7642) correctly ranks a random positive case higher than a random negative case 76.4\% of the time
\end{itemize}

\textbf{Model Selection:} LightGBM with Cross-Entropy loss is selected for final deployment based on its highest validation AUC (0.7642), superior handling of non-linear relationships, and excellent generalization to the test set (AUC 0.7659, gap 0.0017). While blackbox in nature, interpretability is recoverable through SHAP analysis (Section \ref{sec:shap}), providing the best balance of performance and explainability.

%% 4. COST-SENSITIVE THRESHOLD OPTIMIZATION
%% ============================================
\section{Cost-Sensitive Threshold Optimization}

\subsection{Cost Function Design}

Standard metrics (accuracy, F1) fail to capture the 5:1 cost asymmetry between false negatives (default losses) and true negatives (profit). We maximize net cash flow using a custom cost function based on conservative Basel II estimates (50\% LGD) and 10\% profit margin:

\begin{equation}
t^* = \arg\min_{t \in [0,1]} \left[ \text{FN}(t) \times 5 - \text{TN}(t) \times 1 \right]
\end{equation}

\text{\footnotesize Note: False Positives(opportunity costs) are excluded to avoid aggressive lending bias and focus on cash flow.}

\subsection{Threshold Optimization Results}

We compared F1-optimal (standard) vs. Cost-optimal (business-aligned) thresholds for our best linear and tree models. Detailed comparisons are provided in Appendix \ref{app:threshold_table} and visualized in Appendix \ref{app:cost_curves}. The results demonstrate that cost-sensitive optimization yields massive financial improvements, with LightGBM achieving a \textbf{207\% cost reduction} over the F1-optimal baseline.

We select the \textbf{LightGBM Cost-Optimal (0.13)} strategy for production, as it maximizes cashflow while maintaining a manageable risk profile.

\section{Model Interpretation Using SHAP}\label{sec:shap}

\subsection{SHAP Methodology}

We employ SHAP (SHapley Additive exPlanations)\footnote{Lundberg, S.M., \& Lee, S.I. (2017). A unified approach to interpreting model predictions. \textit{Advances in Neural Information Processing Systems}, 30.} to interpret our blackbox LightGBM model. SHAP attributes each prediction to individual feature contributions based on cooperative game theory, ensuring consistent and locally accurate explanations. This approach combines the superior predictive power of tree-based models (AUC 0.7642) with the transparency required for regulatory compliance and business trust.

\subsection{Global Feature Importance}

Appendix \ref{app:shap} details the global feature importance. The top 3 features (MAX\_DELINQUENCY, PAY\_1, DELINQUENCY\_PERSISTENCE) account for $\sim$40\% of total importance, confirming that payment behavior is the primary driver of default risk. Demographic features (Age, Sex, Education, Marriage) rank in the bottom half, contributing less than 6\% combined, which supports fair lending compliance.

\subsection{Local Explanations}

To demonstrate model transparency, we analyze four representative cases (True Positive, True Negative, False Positive, False Negative). These case studies, detailed in Appendix \ref{app:waterfall}, demonstrate how the model relies heavily on recent payment history (PAY\_1) and delinquency magnitude (MAX\_DELINQUENCY). By providing specific reasons for each prediction, we ensure the transparency needed for regulatory compliance.

\textbf{Business Value of Local Explanations:}

\begin{enumerate}
    \item Customer Communication: When rejecting an application, we can cite specific risk factors (e.g., '3 consecutive late payments in the past 6 months') rather than opaque 'algorithmic decision'
    \item Manual Review: Borderline cases (0.10-0.20 probability) can be escalated to human underwriters with SHAP explanations highlighting key risk/protective factors
    \item Model Debugging: Local explanations reveal when the model makes decisions for wrong reasons (e.g., overly relying on credit limit), guiding model improvements
    \item Regulatory Compliance: SHAP provides auditable rationale for each decision, satisfying fair lending regulations and GDPR Article 22
\end{enumerate}

\subsection{Deployment Strategy}

\textbf{Automated Decisioning for Small Loans ($\leq$\$200k):}
To maximize efficiency, we recommend fully automated decisions for small loans:

Auto-Approve ($P < 0.13$): Instantly approves $\sim$40\% of applicants, reducing manual workload.

Auto-Reject ($P \geq 0.13$): Screens out 84.2\% of defaulters automatically.

Large loans should retain human-in-the-loop review using model scores as decision support.

\textbf{Monitoring \& Risk Controls:}
\begin{itemize}
    \item Performance: Track 'Automation Rate' ($>$90\% target) and separate default rates for automated vs. manual segments.
    \item Safeguards: Implement 'Circuit Breakers' to halt auto-approvals if defaults spike ($>$20\%) and pre-model fraud checks.
    \item Fairness: Quarterly audits of approval rates across demographics to ensure unbiased automation.
\end{itemize}

\section{Cost vs Threshold Curves}\label{app:cost_curves}

Figures below show how business cost and F1 loss vary with decision threshold for Logistic Regression and LightGBM models, respectively. These plots demonstrate the fundamental misalignment between traditional metrics (F1-score) and business objectives (minimizing net cost).

\begin{figure}[H]

\includegraphics[width=0.8\textwidth]{../graphs/losses_logistic.png}

\end{figure}

\begin{figure}[H]
\centering
\includegraphics[width=0.8\textwidth]{../graphs/losses_lightgbm.png}
\caption{Business Cost vs F1 Loss for LightGBM across different thresholds. The divergence between F1-optimal and cost-optimal thresholds is even more pronounced, leading to 207\% financial improvement when using business-aligned optimization.}
\label{fig:losses_lightgbm}
\end{figure}

\textbf{Key observations:}
\begin{itemize}
    \item \textbf{Metric Misalignment:} F1-optimal thresholds (0.57 for LR, 0.34 for LGBM) are significantly higher than cost-optimal thresholds (0.39 for LR, 0.13 for LGBM), demonstrating that traditional metrics fail to capture business economics
    \item \textbf{Cost Function Shape:} Both models show U-shaped business cost curves, where too-low thresholds approve too many defaulters (high FN cost) and too-high thresholds reject too many good customers (low TN revenue)
    \item \textbf{Asymmetric Trade-off:} The 5:1 cost ratio (default loss vs profit) drives the optimal point toward conservative lending, favoring lower approval rates to avoid costly false negatives
    \item \textbf{Model Differences:} LightGBM achieves lower absolute business cost at its optimum (-650 vs -536 for LR), validating its superior performance for deployment
\end{itemize}
